## Dispatch pattern — how Claude Code calls Codex

From inside Claude Code, the canonical dispatch surface is `Bash` calling `codex exec` with `--sandbox read-only` for audit work and `--sandbox workspace-write` (the codex default for a trusted project) only for implementation work that is supposed to modify files.

Read-only audit (the dominant pattern this cycle):

```
codex exec --sandbox read-only \
  -c model="gpt-5.3-codex-spark" \
  "<bounded task brief>" \
  > /tmp/codex-spark-audit-<team>.log 2>&1
```

Implementation pass (only when modifying repo files):

```
codex exec \
  -c model="gpt-5.3-codex-spark" \
  "<bounded task brief>"
```

Best practice is to:

1. Pass the brief as a single string argument so stdin remains clean.
2. Tell the model where to write its output (e.g. `Write the report to docs/codex-spark-audits/<team>.md`).
3. Demand a structured verdict on the LAST line in JSON form (this is the same pattern Cato uses at the protocol level via `--output-schema`).
4. Cap model context by passing only the file paths the team needs to read; codex follows them with its own tools rather than us pre-loading everything.

`codex exec` runs in the foreground by default. To dispatch multiple audits concurrently from Claude Code, wrap them in `Bash(... run_in_background: true)`. Each background dispatch returns its own task ID; we then read the per-team output file once it lands.

## Parallel-safety rules

| Concern | Rule | Rationale |
|---|---|---|
| Two read-only audits at once | ✅ safe | each opens its own session; --sandbox read-only forbids file mutation |
| Read-only + Claude Code main-thread Read/Grep | ✅ safe | reads don't conflict |
| Read-only + Claude Code main-thread Edit/Write | ✅ safe | the agent can't write back; no race |
| Multiple write-permitted Codex agents at once on same repo | ❌ forbidden | classic race-drift pattern; see `feedback_forge_race_scope_drift.md` — main-thread + background-Forge can clobber each other; use `isolation: "worktree"` if multiple writers needed |
| Background write-Codex + main-thread edit | ❌ forbidden | same race; suspend main-thread edits until the agent reports done |
| Long-running audit (xhigh reasoning) | ⚠️ ~5-15 min wall clock per agent | dispatch via `run_in_background: true`; use the task ID to fetch output; do NOT poll in a sleep loop |
| Codex output to repo `docs/` | ✅ when read-only audit writes a single .md | each team writes to its own filename under `docs/codex-spark-audits/`; no shared mutable state between teams |
| Codex modifies `package.json` / `src/` mid-cycle | ⚠️ requires worktree | use the worktree-isolation pattern from cycle-2 markets-V3 sprint |

## Rate, cost, safety guardrails

- **Rate limits:** xhigh reasoning runs spend tokens disproportionately on internal CoT. Each ping/pong probe burned ~7k-9k tokens. A multi-paragraph audit will spend 30k-100k tokens. Seven parallel audits ≈ 250k-700k tokens of single-cycle Codex spend — budget accordingly.
- **Cost telemetry:** codex spend is on Torrey's existing OpenAI billing account (no PAI-side meter). Watch the OpenAI dashboard if running >10 audits in a day.
- **Sandbox:** every audit uses `--sandbox read-only` unless explicitly modifying repo files; this is the load-bearing safety boundary.
- **Approval mode:** `approval = never` is the codex default for trusted projects (see `~/.codex/config.toml`). This is appropriate because (a) sandbox=read-only forbids destructive ops by construction, and (b) interactive approval prompts would block parallel dispatch.
- **Evidence logging:** every dispatch logs `model_used`, `tokens_used`, `wall_clock_ms` to the audit's evidence appendix. No model misrepresentation; the appendix is the receipt.
- **Anti-fabrication:** every brief explicitly forbids invention of license #, designations, MLS membership status, sales counts, awards, and Spanish-language status. Geographic guardrail (Boca/Delray/Palm = Palm Beach County; everything else in scope = Broward County) is repeated in every brief.

## Evidence-logging format (canonical)

Every audit Markdown file ends with a fixed evidence block:

```markdown
## Evidence appendix

- **Model used:** `<id>` (e.g. `gpt-5.3-codex-spark`)
- **Reasoning effort:** xhigh
- **Sandbox:** read-only
- **Tokens used:** <N>
- **Wall clock:** <ms>
- **Brief hash:** sha256 of the prompt (optional but recommended)
- **Repository state:** commit `<sha>` at dispatch

- **Structured verdict:** `{"verdict":"pass|concerns|fail|skipped","completeness":"full|partial","top_concerns":[...]}`
```

Verdict on the LAST line of the file is preserved as defense-in-depth even where the schema-enforced output mode is not in use; cycle 2 lost a Cato verdict to model-discretion truncation ([feedback_cato_structured_verdict_prompt.md](../../../.claude/projects/-home-torrey/memory/feedback_cato_structured_verdict_prompt.md)) and the protocol-level fix is documented in Algorithm v6.4.0 R9.
